A very small integration idea

Put a good copy button where the thinking leaves the tool.

Small tools already know useful context. Instead of embedding a chatbot, package that context, copy it, and continue in whatever LLM you already use.

tool state→useful prompt / JSON / Markdown→clipboard No API key. No model choice baked into the tool.
What this repo is actually about

Not seven architectures. Seven places where copy/paste is enough.

These examples stay close to the way the pattern is used in real small tools: the page already has context, a button turns it into something useful for an LLM, and the human carries it across.

Both people get the same questions and JSON return shape. Their reviewed answers are then merged into a neutral meeting brief.

Person B

Same questions. Own perspective.

The useful rule

Use copy/paste until copy/paste becomes the problem.

If the workflow is occasional, human-reviewed and already happening in a browser, this can be enough. If you need background execution, guaranteed sync, many participants or repeated machine-to-machine calls, then you have evidence that it is time for API, MCP or something heavier.
